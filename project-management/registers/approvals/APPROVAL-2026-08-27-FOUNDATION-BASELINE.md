# Approval Checkpoint - Foundation Baseline

Date: 2026-08-27
Status: APPROVED
Approved by: Project Owner

## Approved Baseline

The following project artifacts and operating rules are approved as the governing baseline for the Power Apps learning and implementation project:

- Full application direction for a Microsoft Teams-hosted, multi-tool Canvas App.
- Tool 01 - AI Prompt Capture, Submission and Verification.
- Tool 02 - AI Prompt Chatbot as a confirmed future tool within the same application shell.
- Submitter, peer-rater, verifier, and administrator role layers.
- Minimum two formal verifiers before final completion.
- Verifiers may request changes; administrator retains rejection authority.
- Optional pre-submission peer-rating stage.
- Microsoft Lists / SharePoint Lists as the initial Tool 01 data platform.
- Multi-step guided prompt-submission experience with a meaningful completion indicator.
- Separate Prompt Submission, Peer Rating, and Formal Review records where appropriate.
- GitHub as the durable source of truth for project state, design, decisions, gates, tickets, evidence, and progress.
- GitHub Issues as the gate and ticket system.
- Process & Progress Framework for Learning Phase -> Lab -> Demonstration -> Understanding -> Validation -> Gate Decision -> Next Phase.
- Chat-session operating model with specialist chats and controlled ticket batches.
- Session capacity rule: maximum 5 ticket points and maximum 5 tickets per session batch, with one active ticket at a time.
- Power Apps hierarchy learning/build roadmap as the approved direction for progressive implementation.
- Future agent-orchestration architecture based on the proven human process, including specialist agents, validation roles, structured handoffs, and human approval boundaries.
- Future-first Power Apps standard: use the latest production-suitable Power Apps capabilities, functions, controls, tooling, and supported software versions at the time each ticket is executed.

## Future-First Rule

The project must not intentionally teach or implement retired, legacy, or superseded Power Apps patterns when a newer supported production capability is available.

For version-sensitive technical work, current Microsoft documentation, current release information, current control/function behavior, and current production support status must be checked before implementation.

Generally Available capabilities are preferred for production. Preview capabilities may be evaluated only when explicitly identified as preview and when their risk is acceptable for the specific ticket. Planned but unreleased functionality may influence architecture but must not be represented as an available production dependency.

## Change Control

This approval establishes the current baseline. Any later change that materially alters the approved architecture, process model, security model, learning roadmap, gate model, session-capacity model, or future-first rule must be recorded as a new decision/change and must not silently replace this baseline.
